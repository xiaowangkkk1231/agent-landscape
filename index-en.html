Quick picker: start from your constraints

Don't start from the most popular project. Start from what you are actually constrained by.

Ship an AI app for the business within two weeks
Dify or n8n: build it visually and self-host. Don't write your own framework.
Complex multi-step flows that can pause and wait for human approval
LangGraph first; for multi-role collaboration look at AutoGen, for a .NET enterprise stack at Semantic Kernel.
You just want to write code faster yourself
Claude Code / Codex in the terminal, Cline / Continue inside the IDE.
The agent needs to click through web pages on its own
browser-use is the fastest to integrate; if you already have an agent, add playwright-mcp.
Too many company documents, and support or internal Q&A keeps getting it wrong
RAGFlow for hard documents, LlamaIndex if you want to own the retrieval chain.
You're about to execute model-generated code and want to avoid a disaster
An E2B sandbox plus an allow-listed network. Never run it bare on the host.
Quantify quality before launch, and see what it did after launch
DeepEval puts evals in CI, Langfuse shows end-to-end traces; if you only want traces first, AgentOps.
A real-time voice agent that can be interrupted, with low latency
Pipecat to wire the STT/LLM/TTS pipeline yourself; if you already have WebRTC, LiveKit Agents.
The agent should remember a user's preferences across sessions
Mem0 / supermemory are the fastest APIs; for graph reasoning see cognee, for memory scheduling research see MemOS.
Turn a working flow into a small model and stop paying per-token
Training stack: verl (widest ecosystem) or slime (long trajectories); to try GRPO quickly, ART; align environments on OpenEnv.

Learning path: from the first loop to reliable evaluation

Go in order. Links point to the course publisher, the framework maintainer or the official benchmark page.

1. Decide whether you need an agent at all: Building effective agents · Anthropic
First separate a fixed workflow from an agent where the model chooses the next step; then learn prompt chaining, routing, parallelization, orchestrator-workers and evaluator-optimizer. Exercise: draw both a workflow and an agent loop for one task, then justify the simplest one that suffices.
2. Build your first tool agent: AI Agents Course · Hugging Face
Learn tool calling and the agent loop through Think → Act → Observe, then build and publish Alfred with smolagents. Beginner-friendly, with exercises and unit quizzes.
3. State, recovery and human-in-the-loop: AI Agents in LangGraph · DeepLearning.AI / LangChain
About 1h47m: write the agent by hand, then rebuild it in LangGraph, covering persistence, streaming and human intervention. Exercise: a research flow that resumes after an interruption and requires approval for critical actions.
4. Compare the official stacks side by side · OpenAI Agents SDK · Google ADK · Microsoft Agent Framework
Compare tools, handoffs, sessions, workflows, guardrails and tracing; build the same small task with each official quickstart instead of picking a framework from a tutorial screenshot.
5. Validate with external benchmarks, not the agent grading itself · SWE-bench · OSWorld · WebArena · τ-bench · Terminal-Bench
Pick the benchmark that matches the task: coding, desktop, browser, tool interaction or terminal. Run a single sample first and record environment, model, tools, full trajectory, success rate, retries, latency and cost; only compare leaderboard numbers when the configuration matches.

Practice projects: (1) a minimal tool agent (schema, timeouts, step limits); (2) a resumable research agent (search, citations, drafting, fact-checking); (3) a small coding agent validated by tests it cannot edit. Locate the concrete failure of a single agent before reaching for multiple agents.

Research front: papers and benchmarks (2025–2026)

Work from universities and research labs that changes how agents are designed or evaluated; click a title for the original.

Agent Skills for Large Language Models · Multi-institution survey
Skills became the main line of 2026 agent architecture: the SKILL.md spec, progressive loading, and how they complement MCP. Also the first systematic look at skill security — 26.1% of community skills carry vulnerabilities.
Agentic Tool Use in Large Language Models · HIT Shenzhen · TikTok
Reads tool-use research as three eras — prompting, supervised tool learning, RL tool policies — with a three-tier benchmark map spanning BFCL, SWE-bench, OSWorld and τ-bench.
A Survey on Evaluation of LLM-based Agents · Hebrew University · IBM Research · Yale (ACL 2026 Findings)
The evaluation landscape from single-turn scores to trajectory-level assessment, with a capability comparison of Langfuse, Arize, LangSmith and other eval frameworks.
From LLM Reasoning to Autonomous AI Agents · Multi-institution survey
A taxonomy of 60+ benchmarks across 8 capability domains: one model scores 87% on SWE-bench and 44% on GAIA, so picking an agent from a single number goes wrong.
Recognize Your Orchestrator: the scheduler is the bottleneck · Nanjing University NLP · State Key Lab for Novel Software Technology (ICML 2026)
Failure attribution across Deep Research, Agent Coder, GUI Browser and Agentic RAG: the orchestrator carries 63.8% of failures on average, executors only 32.4%. Also finds a "reasoning trap" — the longer it thinks, the less room it leaves for observing external signals.
Context Engineering: From Prompts to Corporate Multi-Agent Architecture · arXiv 2603.09619 (single-author preprint, 2026-03)
Treats context as the agent's operating system and proposes five quality criteria — relevance, sufficiency, isolation, economy, traceability — then stacks intent and specification on top into a four-level maturity pyramid. The author calls it a framework, not evidence; use it as vocabulary rather than conclusions.
SETA: environments at scale for terminal agents · CAMEL-AI · Imperial · UCL · Oxford · KAUST · Stanford · SambaNova (arXiv 2607.10891)
SETA-Synth and SETA-Evol share one verification mechanism and produce 4,500+ verifiable terminal environments, the largest open terminal RL environment set; Qwen3-8B with GRPO reaches 12% on Terminal-Bench 2.0, the best among RL models of that size.
Environment Evolution: environments should get harder with the model · Tencent Hunyuan (arXiv 2609.04128)
Environments synthesized from scratch are already too easy for frontier models and give no learning signal; raising difficulty off-policy generation by generation yields +14.4 and +18.0 points for Qwen3.6-27B/35B-A3B on Terminal-Bench 2.1.
BIRD-RL: agentic RL in stateful data environments · arXiv 2610.29426
Tool-centric environments don't fit stateful tasks like SQL debugging: one database per trajectory is too expensive, a shared one contaminates. A trajectory-scoped persistent execution facility reuses database copies, lifting space efficiency 12.8×, with 7B/14B models at 44.4% / 48.0% success.
ASCon: a unified representation for multi-agent failure attribution · arXiv 2608.10646
Who failed, at which step, and in what failure mode share the same trajectory evidence, yet each used to train its own model. Direction-aware graph attention improves faulty-agent identification by 5.83, faulty-step identification by 10.63 and failure-mode Macro-F1 by 14.73.
C-World: an environment creator for computer-use agents · UC San Diego (ACL 2026)
Creates training and evaluation environments on demand: 5,571 tools, 204 real applications, injectable faults; fine-tuning on 1,170 trajectories beats a 119k-sample baseline.
AGENCYBENCH: a million-token benchmark of autonomous agents in real scenarios · SJTU · GAIR · Shanghai Innovation Institute (ACL 2026)
Long-horizon real tasks: about 1M tokens, 90 tool calls and several hours per task; closed models average 48.4%, open models 32.1%.
AgentGym2: de-idealized evaluation in the real world · ACL 2026
Deliberately injects noise, underspecified instructions and a tool-discovery phase; all 15 frontier models struggle.
EvoClaw: evaluating agents on continuous software evolution · USC · Princeton (ICML 2026)
Rebuilds open-source commit history into an executable milestone DAG: above 80% on standalone tasks, but at most 38% in continuous evolution.
Agent Planning Benchmark (APB) · arXiv 2606.04874
Tests planning on its own, including broken tools and unsolvable tasks: producing a plausible plan does not mean recognizing that the plan cannot run.
Agentic Abstention: does the agent know when to stop? · Hugging Face Daily Papers (2026-06)
Models "keep going, stop or abstain" as a sequential decision problem — long-horizon agents usually fail not at one wrong step but by not stopping.
ToolVerse: environments for agentic RL · arXiv 2607.15660
Extends agentic RL to nearly 400 real MCP environments and about 4,500 tools: the training bottleneck is shifting from algorithms to environments and verifiers.
Memora: forgetting-aware memory · arXiv 2604.20006
Memory's first-class question moves from "can it remember" to "when should it forget": the FAMA metric explicitly penalizes using stale memories, and several memory agents fall for it.
